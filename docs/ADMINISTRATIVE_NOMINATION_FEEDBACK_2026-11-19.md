## Integration order

1. Implement the Word template, client fields, municipality, and billing picker independently.
2. Wire the form to saved nominations and expose it beside the existing instructions export. The arrival day uses the PEDR ETA when available, then the nomination ETA, displayed in the agency's Caracas time zone. The SN/OT reference uses the agency's notice format, including the branch code when available.
3. Verify mapping, empty fields on pre-existing records, multiline instructions, billing persistence, and the original operational export. Verify the three additive migrations on a disposable PostgreSQL instance before applying them in production.
4. Review and configure real client instructions, port municipalities, and per-nomination billing selections in the app. The example is not seed data.

## Local validation

- The production build, workspace typecheck, and lint pass. The shared schema, backend, and frontend suites pass all 876 tests.
- The Word download test exercises the HTTP route and JWT authentication and verifies the populated DOCX. Billing route tests cover independent recipients, address snapshots, clearing one category, invalid input, and cancelled nominations. The HTTP tests use database fixtures at the Prisma boundary.
- The source example renders on one page with the original quality header and logo. Long text and fiscal addresses flow across pages with page numbering and a repeated header.
- Prisma client generation and the offline schema comparison pass. The sandbox blocks the disposable PostgreSQL process, so execution of the three additive migrations against PostgreSQL is still pending.
