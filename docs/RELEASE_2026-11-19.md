# Portlog release preparation — 19 November 2026

The release combines the administrative nomination work at `9149ca4` with the
security maintenance reviewed in PR #17. Main still starts the legacy host deploy;
all PR checks, backup verification, and isolated restore rehearsal must pass before
it advances. PR workflows check out the full candidate SHA explicitly.

## Compatibility changes

- Upgrade vulnerable runtime dependencies while retaining Prisma 6 and PostgreSQL 16. The Prisma CLI is a runtime dependency; build/test dependencies are pruned
  from the backend image after compilation. The image removes npm and its
  vulnerable vendored tools; startup invokes the installed Prisma CLI directly
  through Node, without an installer or package download.
- Upgrade Zod and its Nest/React Hook Form adapters. PATCH schemas explicitly
  preserve omitted fields, including collection and scalar create defaults.
  Regression tests cover client/contact details, nomination routing and billing,
  and document template settings.
- MinIO SDK 8.0.7 remains pinned. Its query-string dependency is upgraded to
  10.0.0; a checked postinstall adapter changes its namespace imports to default
  imports in both published builds. Both Docker build contexts include this
  adapter. Jest transforms the three ESM query-string packages.
- The PostgreSQL image retains the upstream 16.16 database binaries and entrypoint,
  replacing the obsolete Go-based gosu with Alpine's native su-exec. The entrypoint
  replacement is checked during the build. Keep `portlog_postgres-data` intact.
- The Certbot image removes pip after installation. The reported vulnerable
  packages are pip's vendored dependencies, not Certbot's installed dependencies.
  Certificate issuance and renewal do not require pip. Keep existing TLS files.
- Cypress skips throttling only for `NODE_ENV=test`. Tests verify the sixth login
  remains blocked in production, development, and an unset environment.
- `/api/health/ready` probes the database and existing object bucket without
  creating data. It returns 503 without private diagnostics if either is unavailable.

## Silo scanner finding

The digest-pinned Silo Server 20261112 includes the CSV fix `3252d5b7f` and the
JSON Lines SIMD follow-up `fd69c89d0` for CVE-2026-39414. The fork retains the
upstream module identifier, causing an upstream MinIO advisory to match it.
[Silo's advisory ledger](https://silo.pgsty.com/about/security-advisories/#cve-2026-39414--s3-select-oversized-record-memory-exhaustion)
documents both fixes.

`security/silo-trivy-ignore.yaml` limits the exception to this CVE, binary path,
and exact module version, and expires on 19 December 2026. Other findings remain
blocking. `scripts/check-silo-record-limits.cjs` proves normal CSV and JSON Lines
records can be selected and records exceeding 1 MiB are rejected. It requires an
explicit isolated-fixture flag and can connect only to localhost with fixture
credentials. The CI storage compatibility job runs it after the legacy-to-Silo
upgrade. No unfixed vulnerability is accepted by this exception.
